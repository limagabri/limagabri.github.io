# Gabriel Contact Page Constitution

## Core Principles

### I. Approved identity and content
The page MUST preserve PROFILE_CONTENT.md destinations, ordering, name, and bilingual introduction.
No invented biography, portrait, status, slogan, or contact channel may be published.
Owner changes take precedence over older planning text.

### II. Accessible mobile experience
All actions MUST be native links or buttons with visible keyboard focus, accessible names,
44px minimum targets, sufficient contrast, reduced-motion support, and no 320px overflow.
The compact navy, purple, and teal presentation MUST remain usable with zoom and safe areas.

### III. Predictable language and privacy
Every fresh load MUST start in English. Manual Portuguese selection MUST update document
language and accessible copy in memory only. No preference storage or browser-language detection.
The static page MUST have no analytics, backend, or third-party runtime requests beyond links.

### IV. Maintainable proportional implementation
Use React, TypeScript, and Vite with local assets. Centralize ordered bilingual profile data.
The photo MUST be replaceable at public/images/profile.jpg without component edits; unavailable
or broken photos MUST show GL. Dependencies MUST serve a concrete requirement.

### V. Evidence before completion
Builds, behavioral tests, browser checks, and production verification MUST report actual results.
Official Spec Kit artifacts and execution evidence MUST be retained. Unrun checks cannot pass.
Missing profile assets or unverified deployment MUST remain explicit limitations.

## Product Constraints
The root contact hub MUST retain its six unified cards including Lattes and all existing behavior.
No portfolio, copy action, email, phone, downloads, emojis, or em dashes in product copy.
The owner-authorized /qr/ companion MUST show the permanent contact URL as a large high-contrast QR,
name, current local portrait and contact link. It MUST be installable with /qr/ standalone launch
and MUST work offline after its first complete successful load, including photo and local icons.
Its offline storage MUST be isolated from root navigation and MUST NOT persist language preference.
Use recognizable service icons and local assets. Keep https://limagabri.github.io stable.
Actual phone installation and camera scanning MUST be distinguished from automated validation.

## Development Workflow
Follow official installed Codex skills: constitution, specify, plan, tasks, implement, converge.
Review and correct each output before proceeding. Build and browser acceptance precede publication.
Inspect Pages and workflow settings; use an authorized branch/merge path without bypassing protection.
Record external permission failures and real-device verification limits.

## Governance
This constitution governs implementation; explicit owner instructions override it. Amendments MUST
record the reason, review affected specs and tasks, and use semantic versioning: major for incompatible
principles, minor for added rules, patch for clarifications. Every review MUST check these gates.
